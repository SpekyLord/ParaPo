# M3 demo results — 2026-11-07

This records a small local class demo using the images the user supplied in chat. It is not a model comparison or an acceptance result. M3-01–04 are complete for this local set; M3-05–09 are partial, and M3-10 remains undecided.

## Dataset

- 16 images were supplied. Fourteen photos of vehicles/signs are used; poster graphics 06 and 10 are excluded.
- Original image URLs and creator/license details were not supplied. The images, manifests, checkpoints, and exports stay local and ignored by Git. Incidental people and plates are not labels.
- The labels were visually checked against the photos. Clear box errors in images 03, 13, 15, and 16 were corrected. Images 04 and 12 have unreadable text; uncertain transcriptions and route IDs not printed on a sign remain unknown.
- Split: 10 train, 2 validation, 2 test. Images 01 and 02, which may show the same bus, are both in train. A quick exact-hash and 64-bit average-hash check found no exact matches or pairs within 8 bits. Original-source derivatives cannot be traced because the image sources are unknown.
- Frozen manifest: `parapo-m3-user-images-draft-v4-2026-11-07`; SHA-256 `99585a80fac9ebb1ff55a154462810692083200ea971cd8dc50ec91d5617189b`.
- Frozen split record: SHA-256 `2d9ef4d53123e12e6212351e0b168bf1f29aa7a87812ce38139fb6b4f5f03756`.

## YOLOv8n run

Ultralytics YOLOv8n 8.4.203 was fine-tuned from its `yolov8n.pt` initialization on the 10 training images. The run used 320-pixel input, batch 2, seed 42, max 20 epochs and patience 5; early stopping ended at epoch 6, with the best checkpoint from epoch 1. Validation had two images. PyTorch 2.11.0+cu128 ran on the PC's NVIDIA RTX 4050 Laptop GPU. EasyOCR 1.7.2 (English) read both ground-truth and detected crops after 3x cubic enlargement.

The checkpoint was trained on v3. The YOLO training and validation label files were byte-for-byte identical in v3 and v4; v4 corrected only a test box and a validation transcription, so the same checkpoint was used for the final report.

## Export and phone check

The checkpoint exported to ONNX 1.23.2 (12,620,173 bytes; SHA-256 `183a212b84273fc58870bf4dfd10bb76f52cecabf9e0c7ac5b8f1d01563116d8`). ONNX Runtime 1.31.1 was compared with PyTorch CPU on the same four validation/test samples. The parity check failed at 1.5-pixel box and 0.02 score tolerances: the largest score-ordered coordinate difference was 18.144775 pixels and the largest score difference was 0.12714114. Three detections were compared; the other samples had no detections. The detections were false positives, and the export is not treated as phone-ready. Local parity summary: `datasets/m3-samples/runs/demo-v4/parity-result.json`.

No model ran on the phone. The current ADB listing showed the device offline; USB tethering by itself did not make ADB usable. There is no detector inference path in the Android app, and no Android code was changed. Phone latency, memory, FPS, and on-device parity are unmeasured.

## v5 retraining update — 2026-11-07

Four new user-supplied photos were added to a v5 manifest: one CPU windshield placard, two nighttime Route 03 side signs, and one uncertain JARO CPU placard. All four went into training. The frozen split is 14 train / 2 validation / 2 test; validation and test were not used for gradient training. v4 and its earlier run remain unchanged. The existing two-photo test split was already previewed in v4, so v5 test results are exploratory.

Frozen v5 manifest SHA-256: `1408e4a2cc520ad8a2629bbcf95f8ef07a62b6b52a8981890544ee7c65aabfe4`. The final run configuration SHA-256 is `b20f5561f8cb21b4ee22d6775ee166fffa4b7d9a69afaf0fe10025faa816e070`; checkpoint SHA-256 is `e5b619f5d4bd97d67aca16e1a29da955ff1678a2a74c855adc15c53148c09a04`.

YOLOv8n 8.4.203 was retrained from the same COCO-pretrained `yolov8n.pt` hash using 320px input, batch 2, seed 42, max 20 epochs and patience 5. It stopped after 6 epochs; the best checkpoint was epoch 1. A validation-only sweep selected score cutoff 0.01 by maximum F1 across the recorded cutoff grid. On just two validation photos that gave 1/2 true positives and 44 false positives, so the threshold is highly unstable.

At that pinned cutoff the v5 test run found **0/3 true-positive signs** and 53 false positives. AP50 was 0.001026 and AP50–95 was 0.000205. Ground-truth-crop OCR CER was 0.794; route-code accuracy was not estimable. Detector-crop OCR CER was not estimable for the 53 false-positive crops because none overlapped a labeled sign. No route or direction labels were available for the test signs.

The new 12,620,278-byte ONNX export also failed host parity: for the four validation/test images, PyTorch detection counts were 159/97/158/178 while ONNX Runtime counts were 225/158/158/235 at the raw 0.001 floor and NMS IoU 0.7. Keep the scanner disabled. The new export was not installed on the phone. Current phone instrumentation only confirms that the existing bundled provisional model loads and runs on a synthetic image; it is not a v5 phone measurement.

Local v5 records are in `datasets/m3-samples/runs/demo-v5/`; the new checkpoint/export are in `datasets/m3-samples/runs/yolov8n-v5-20ep/`. v5 did not produce useful detector performance or a model winner. SSD MobileNetV2 and EfficientDet-Lite0 still have no comparable training/export path.
