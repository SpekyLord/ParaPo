# Scanner implementation and Tecno checks — 2026-11-08

Later follow-up: [Nov. 9 OCR investigation and minimum-size fix](ocr-2026-11-09.md). The evidence below remains the Nov. 8 baseline. The later bounded crop comparison did not justify general preprocessing, but identified and fixed ML Kit's rejection of undersized input images.

This is a school-prototype implementation/evidence update, not completion of the research study. The Tecno was absent at the start, then connected during implementation. Old reports and manifests remain unchanged. No samples were uploaded and no commit was made.

## What changed

- One bundled ML Kit reader now serves live selected crops, aligned snapshots, and an isolated-test-only diagnostic. The diagnostic displays actual pixels, raw words/EMPTY/error, expected text separately, extracted codes, and route interpretation; labels never enter recognition.
- `03`/`3` identify Route 3 using whole numeric tokens. Exact aliases still work; `13`, `30`, `103`, empty text, unsupported codes, and conflicting evidence retain conservative outcomes. An additional unsupported numeric token prevents a confident alias/code result. Journey preferences never select the interpretation. Shared JSON cases run in Python and Android.
- Experiment records separate raw text, printed numeric tokens, normalized tokens, canonical catalog route IDs, and extraction status. `ROUTE-03`/`ROUTE-10` truth maps deliberately to `ILO-03`/`ILO-10`. Missing extraction is not an OCR error. Unknown transcription and unmatched detector crops are excluded from text-accuracy denominators, with counts retained. Detector/sign truth assignment is one-to-one at IoU 0.5; duplicate detections remain false detections.
- The default camera path is Aim → Read aligned sign → frozen crop. It uses the unresized upright analysis image, shows ML Kit's text, and clears all evidence when resumed/reselected. Frozen results are explicitly about a captured image, without live ownership/stability claims.
- An explicit **Try checked sign detector** option loads the checked experimental v10 artifact, outlines candidates, and reuses sign selection, temporal decisions, and observed-vehicle direction confirmation. Returning to aligned reading or changing target/session clears evidence. Model failure retains Preview and manual navigation. Overlapping candidate signs invalidate association even when one has a dominant overlap score. This remains a heuristic, not proof of ownership.
- Analyzer and Preview share a measured CameraX viewport. The scanner's intended 320dp preview height is retained explicitly; the generic view helper had overwritten that height. Success and failure callbacks carry session/context/target identity. Late callbacks cannot restore an old decision.
- Summary timing is now labeled analyzer-entry-to-UI-update, excluding capture and render presentation. It is not complete capture-to-display latency.

## Export discrepancy: cause and resolution

The v10 PyTorch runner used rectangular auto-padding: validation images 28/32/34 became tensors `1×3×128×320`, `1×3×160×320`, and `1×3×256×320`. Static ONNX used `1×3×320×320`. These were different inputs. Fixing box pairing alone could not explain different counts.

With identical square tensors, PyTorch CPU and desktop ONNX passed. On the phone those prepared tensors also passed, but the original Android Skia resizer differed from OpenCV by up to 10/255 in a pixel channel and changed detections. The failed tensors/outputs remain in `runs/phone-scanner-2026-11-08/files/parity-1794150975279/`.

The deployed and experiment paths now share explicit pixel-center bilinear sampling, round-half-up RGB values, integer centered padding with value 114, RGB NCHW FP32 normalization, and matching inverse box geometry. On all three photos, the Tecno's generated tensor equals the desktop tensor exactly. Both identical-tensor and actual Android-bitmap inference/decoding pass at unchanged 1.5-source-pixel / 0.02-score tolerances. Scores, NMS IoU 0.7, and selected cutoff 0.25 were not relaxed. Empty detections on image 34 remain a miss, not evidence of useful accuracy.
